# rb1-16-band — 完成問題・デバッグ課題・出力予測

## この課題の位置と到達点

- 位置: Ruby 軸 / 基礎 / 課題 16（基礎は全 21 課題）。前は `rb1-15-pattern-matching`、次は `rb1-17-files-io`。
- 到達点: この課題を終えると、次ができるようになる。
  - 途中まで書かれたコードの**残りを設計して埋められる**（穴の中身は指示されない）。
  - 動いてはいるが意図と違うコードについて、**どこが違うのかを自分で見つけて**直せる。
  - Ruby のコードを読んで、実行する前に標準出力を書き下せる。
- ここまでの課題 1〜15 で扱った道具（Array / Hash / Enumerable、ブロック、メソッドの引数、
  クラス、例外、module、値オブジェクト）の範囲で解ける。完成問題で埋める中身と出力予測の対象コードは、
  課題 15 までの手本に出たメソッドだけでできている。
- 例外が 1 つある。デバッグ課題で**与えられる**コードは、手本に出ていないメソッドを 3 つ使っている
  （`Enumerable#max_by` / `Enumerable#sum` / `Float#round`）。読むために要るなら
  https://docs.ruby-lang.org/en/4.0/Enumerable.html と
  https://docs.ruby-lang.org/en/4.0/Float.html で引く。

## 初めて使う道具

なし。この課題で新しく入れる道具・新しく覚えるコマンドは無い。

## 前提

- 課題 1 で作った成果リポに `Gemfile` / `.ruby-version` があり、`bundle install` が済んでいること。
- 教材リポ（このファイルがあるリポジトリ）で `bundle install` が済んでいること。
- 課題 12 を終えていること。課題 12 で説明した「中身を読めない判定テスト」がこの課題にも 1 つある。
- 封緘の鍵が `~/.config/ruby-learning/seal.key` にあること（確かめ方は課題 1 の README の手順 3）。
  無いと `bin/check` は終了コード 2 で止まる。
- 課題 3・7・9・10・11・13・14 を終えていること。

以降、`<成果リポ>` は自分の成果リポジトリのパス、`<教材リポ>` はこのファイルがあるリポジトリのパスを指す。

この課題には「なぜこう書くか」欄も模範解説もない。手本を書き写す課題ではなく、
自分で書く・直す・読むことが中身だから。

## 手順

1. 作業場所を作る。

   ```sh
   cd <成果リポ>
   mkdir -p rb1-16-band/complete/lib rb1-16-band/debug/lib rb1-16-band/predict
   ```

2. **完成問題**。雛形をコピーし、3 か所の穴を埋める。

   ```sh
   cd <成果リポ>
   cp <教材リポ>/tasks/rb1-16-band/complete/lib/tally_report.rb rb1-16-band/complete/lib/tally_report.rb
   ```

   埋める中身は、それぞれの穴のすぐ上のコメントが決めている。
   このファイルの判定テストは中身を読めない（判定のときだけ走る）。コメントに書いていない条件は
   問われないので、コメントを仕様として読む。自分でも小さなテストを書いて確かめながら進めてよい。

3. **デバッグ課題**。壊れたコードをコピーする。判定テストは教材リポ側のものをそのまま走らせる。

   ```sh
   cd <成果リポ>
   cp <教材リポ>/tasks/rb1-16-band/debug/lib/word_stats.rb rb1-16-band/debug/lib/word_stats.rb
   ```

   ```sh
   cd <成果リポ>
   bundle exec ruby -Irb1-16-band/debug/lib <教材リポ>/tasks/rb1-16-band/debug/test/word_stats_test.rb
   ```

   テストは読んでよい（`<教材リポ>/tasks/rb1-16-band/debug/test/word_stats_test.rb`）。
   **どこが壊れているかは書かれていない。** 各メソッドのすぐ上のコメントが意図の正で、
   そのコメントは直さない。テストが全部通るまでコードの側を直す。

4. **出力予測**。対象コードを読み、実行する前に標準出力を書き下す。

   エディタで `<成果リポ>/rb1-16-band/predict/01.txt` を新規作成して開く
   （課題 2〜11 で手本を写したときと同じ言い方）。

   対象コードは `<教材リポ>/tasks/rb1-16-band/predict/01.rb`。読むだけで、**まだ実行しない**。
   1 行ずつ、何が出るかを書く。書き終えてから実行して照合してよい。

   ```sh
   cd <教材リポ>
   bundle exec ruby tasks/rb1-16-band/predict/01.rb
   ```

   先に実行してしまうとこの課題の意味が無くなるので、順序は規約として守る
   （機械は順序を見ていない）。

5. 判定する。

   ```sh
   cd <教材リポ>
   bin/check rb1-16-band <成果リポ>
   ```

   完成問題が落ちたときに出るのは「テスト名と失敗メッセージの 1 行目」だけで、
   正解のコードは出ない。出力予測が落ちたときに出るのは「最初に食い違う行番号」だけで、
   正しい出力は出ない。

## 完了の判定

`bin/check rb1-16-band <成果リポ>` の 3 項目（完成問題の判定テスト / デバッグ課題のテスト /
出力予測 01）がすべて「合格」で、終了コードが 0 になること。終了コードは `echo $?` で見る。
