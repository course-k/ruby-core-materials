## 教材コード

1. **課題 10 のクラスメソッドの底本を Singleton Classes 節へ移した。** 再オープンの例は
   「Ruby in Twenty Minutes」第 3 部どおり `attr_accessor` の追加だけに戻したので、
   B8 行の「クラスメソッド」を Modules and Classes の Singleton Classes 節の
   `class C / class << self` と `def my_method / 1 + 1` の連結で置き替えた。
2. **課題 10 の `to_s` は既定の挙動を確かめる形にした。** 原本の非空・非コメント行を 80 行以内に
   収めるため、独立したテストメソッドを作らず `inspect` のテストに 1 行足した（現在 79 行）。
3. **課題 11 の `retry` のテストは試行回数を測らず、`assert_raises(RuntimeError)` で
   「諦めて再送出する」ことだけを確かめる。** 原文の `puts` を落とすと回数を観測する手段が
   無くなるため。原文の `if/else` と `raise` は保った。
4. **出力予測の対象コードは、出力を `inspect` ではなく `join` した文字列にした。**
   Hash / Array の `inspect` の書式を示す手本が課題 7・9 の時点に無いため。
   課題 16 も同じ形に揃えた。
5. **課題 16 の予測コードの置き替えの選び方**: `min_by(&:pages)` → `sort_by(&:pages)[0]`、
   `partition` → `select` と `reject` の 2 つの `size`、`Hash.new(0)` →
   `each_with_object({})` と `(acc[k] || 0)`。いずれも課題 15 までの手本に出た形。
6. **課題 16 のデバッグ課題の与えられたコードは直さなかった。** `max_by` / `sum` / `round` は
   手本に出ていないが、学習者が**読む**側のコードであり、直すと仕込んだ欠陥の位置が動く。
   代わりに README に「この 3 つは手本に無い。要るなら公式ドキュメントで引く」と書いた。

## 判定機構

7. **`check.yml` の `runs_min` を任意キーにした。** 省略または 0 のときはテストメソッド数を見ない。
   スキーマは `docs/check-yml.md`。
8. **失敗メッセージ 1 行の上限を 200 文字（文字数。バイト数ではない）とし、
   超えたら末尾に `…` を付ける。** 根幹 §6 は「1 行目に限る」としか書いていない。
9. **禁止トークンの静的検査は封緘テストの中のテストメソッドとして実装した。**
   設計 §5 の judge 表に「制約の静的検査」の行は足していない（教材側を設計文書に合わせる指示が
   無かったため）。検査する語は、課題 12・21 の要件の「制約」節に列挙された語のうち、
   正規表現で当てられるものに限った（課題 12 は 20 語、課題 21 は 9 語）。
   失敗表示は当たった語だけを 1 行で出し、提出ファイルの原文も正規表現一覧も出さない。

## 課題文書

10. **封緘の鍵の入手元を「教材の作成者から受け取る」とした。** 封緘は教材作成時の鍵で掛かっており、
    学習者が鍵を生成しても開かない。根幹 §6 は鍵の置き場所しか定めていない。
11. **設計 §3.2 の「初めて使う道具」の表は課題 1 に封緘を挙げていないが、課題 1 の道具節に
    8 件目として「封緘と鍵」を足した。** 鍵の置き方をどこにも書かないと課題 12・16・20・21 に
    着手できないため。
12. **課題 5 の道具節を 3 件から 5 件にした**（パイプ `|`、`printf ... > ファイル`）。
    設計 §3.2 の表は課題 5 に 3 件を挙げているが、課題 19 の確認手順がこの 2 つを使う。
13. **書き写し 16 課題の完了判定の非機械工程を 2 件に揃えた**（`why.md` を模範解説より先に書いた／
    模範解説を読んで書き足した）。課題 2〜11 は 1 件だったので 2 件へ増やす側で統一した。
14. **課題 16 の前提に鍵の行を足し、課題 12・20・21 と同じ文面にした。**
15. **課題 20 の実行例は `<ファイル名>` / `<自分で決めた呼び出し>` のプレースホルダにした。**
    封緘仕様が定める名前空間・関数名を README に出さないため。
16. **課題 12・21 の動作確認の手順は「開封した要件の『例』の節の入力をファイルに書いて流す」と
    指し、入力のリテラルを README に書かない。**
17. **課題 1 の `git config user.name` / `user.email` は「未設定の環境でのみ」と添えた。**
