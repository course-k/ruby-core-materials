# rb1-20-zero-impl — 仕様だけからゼロで実装する 3 題

## この課題の位置と到達点

- 位置: Ruby 軸 / 基礎 / 課題 20（基礎は全 21 課題）。前は `rb1-19-optparse-executable`、次は `rb1-21-mini-integration-2`。
- 到達点: この課題を終えると、次ができるようになる。
  - 手本も雛形の骨組みも無い状態から、**仕様の文面だけを頼りに**小さなプログラムを書ける。
  - 仕様の境界条件（空のとき・数が足りないとき・形が違うとき）を、自分で拾って実装に反映できる。
  - 自分の実装と参照実装を読み比べて、違いを言葉にできる。
- この形式は基礎の出口（基礎を終えて中級へ移るときの判定課題）と同じ形。ここで 3 回練習する。

## 初めて使う道具

なし。この課題で新しく入れる道具・新しく覚えるコマンドは無い。
封緘物の開封（`bin/check --start`）は課題 12 で説明した。この課題では**完了後に開くもの**
（参照実装）が初めて出てくる。全部の判定に合格した回の `bin/check` が自動で開く。

## 前提

- 課題 1 で作った成果リポに `Gemfile` / `.ruby-version` があり、`bundle install` が済んでいること。
- 教材リポ（このファイルがあるリポジトリ）で `bundle install` が済んでいること。
- 課題 19 までをすべて終えていること。
- 封緘の鍵が `~/.config/ruby-learning/seal.key` にあること（確かめ方は課題 1 の README の手順 3）。
  無いと `bin/check` は終了コード 2 で止まる。

以降、`<成果リポ>` は自分の成果リポジトリのパス、`<教材リポ>` はこのファイルがあるリポジトリのパスを指す。

## 手順

1. 着手して 3 つの仕様を開く。

   ```sh
   cd <教材リポ>
   bin/check --start rb1-20-zero-impl <成果リポ>
   ```

   `<教材リポ>/unsealed/rb1-20-zero-impl/` に 3 つの仕様（`spec_01_normalizer.md` /
   `spec_02_ledger.md` / `spec_03_log_reader.md`）が開かれる。
   **判定条件の正本はこの 3 ファイル**で、README は手順だけを持つ。

2. 雛形を置く。

   ```sh
   cd <成果リポ>
   mkdir -p rb1-20-zero-impl/lib
   cp <教材リポ>/tasks/rb1-20-zero-impl/template/lib/normalizer.rb  rb1-20-zero-impl/lib/normalizer.rb
   cp <教材リポ>/tasks/rb1-20-zero-impl/template/lib/ledger.rb      rb1-20-zero-impl/lib/ledger.rb
   cp <教材リポ>/tasks/rb1-20-zero-impl/template/lib/log_reader.rb  rb1-20-zero-impl/lib/log_reader.rb
   ```

   3 つとも中身は 1 行だけ（`# frozen_string_literal: true`）。メソッド名も骨組みも
   入っていないのは、そこを決めることがこの課題の中身だから。

3. 1 題ずつ実装する。3 題は独立していて、どの順で解いてもよい。
   実装しながら自分で小さなテストを書いて確かめてよい（置き場所は
   `<成果リポ>/rb1-20-zero-impl/test/` などで自由。判定には使われない）。

   手元で試すときは、`-I` でこの課題の `lib` を読み込み先に足して 1 行だけ走らせるとよい。
   `<...>` の部分は、自分が仕様から決めたファイル名・名前空間・メソッド名に置き替える。

   ```sh
   cd <成果リポ>
   bundle exec ruby -Irb1-20-zero-impl/lib -e 'require "<ファイル名>"; p <自分で決めた呼び出し>'
   ```

4. 書式を整える。RuboCop はこの課題の判定に含まれない。自分で掛けて直す。

   ```sh
   cd <教材リポ>
   bundle exec rubocop --config .rubocop.yml <成果リポ>/rb1-20-zero-impl/lib
   ```

5. 判定する。3 題のうち解けたものから順に合格が付く。

   ```sh
   cd <教材リポ>
   bin/check rb1-20-zero-impl <成果リポ>
   ```

   落ちたときに見えるのはテスト名と失敗メッセージの 1 行目だけ。テスト名は仕様に出てくる語だけで
   できているので、仕様のどの条項が通っていないかはテスト名から辿れる。

6. 3 題すべてが合格すると、その回の `bin/check` が**参照実装**を
   `<教材リポ>/unsealed/rb1-20-zero-impl/` に開く（`reference_01_normalizer.rb` など）。
   自分の実装と読み比べ、違いを 7 の記録に書く。参照実装は唯一の正解ではない。

## 完了の判定

次の 2 つが揃ったらこの課題は完了。

- `bin/check rb1-20-zero-impl <成果リポ>` の 3 項目（ゼロ実装 01 / 02 / 03）がすべて「合格」で、
  終了コードが 0 になる（`echo $?` で見る）。判定条件の正本は開封した 3 つの仕様の「完了条件」の節。
- 開封された 3 つの参照実装を読み、自分の実装との違いを `progress.md` に書いた。

## 進捗の記録

記録先は成果リポの `progress.md`。ただし**課題ごとの表は手で書かない**——
`bin/check` が `.check/` から状態と日付を書き直している。手で足しても次に
`bin/check` を走らせたときに消える。開いて自分の行が入っていることだけ確かめる。

振り返りは `rb1-20-zero-impl/notes.md` に書く（新規に作る）。表の「なぜこう書くか」欄が
このファイルへのリンクになる。書く内容:

- 3 題それぞれで、仕様のどの境界条件を最初に読み落としたか。
- 参照実装と自分の実装で、いちばん違っていた点。
- 自分の書き方のほうがよいと思った点があれば、その理由。

`progress.md` に自分で書くのは、週あたりの目標・未消化にした課題・想起セッションの記録の
3 つだけ。書いたらコミットする。

書いたらコミットする。

```sh
cd <成果リポ>
git add .
git commit -m "rb1-20: 仕様からのゼロ実装 3 題を解いた"
```
